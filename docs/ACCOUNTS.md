# 계정·기록·백업 사용 안내

회원가입은 현재 브라우저에 개인 학습 프로필을 만듭니다. 이메일·외부 서버·유료 API가 필요하지 않습니다. 로그인 전에도 게스트로 학습할 수 있습니다.

아이디는 영문·숫자·`_`·`-` 3~32자이며 이메일 주소를 사용하지 않습니다. 회원가입과 로그인은 HTTPS 또는 신뢰할 수 있는 localhost에서 Web Crypto를 사용할 수 있어야 합니다. HTTP에서는 입력과 제출을 비활성화하고 HTTPS 안내를 표시합니다. 저장소 API도 암호화 기능과 연결 상태를 먼저 확인하므로 이 경우를 비밀번호 오류로 표시하지 않습니다. 비밀번호 검증 방식과 기존 저장 키는 유지합니다.

현재 접속 주소는 `https://insuham0315.github.io/Security_CBT/`입니다. 기록은 브라우저와 출처(프로토콜·도메인·포트)에 연결되므로 `insuham0315.github.io`와 `ist-security.kro.kr`의 로컬 기록은 서로 독립적입니다. 도메인을 바꿔도 기존 출처의 데이터를 삭제하지 않으며, 다른 출처에서 계속 쓰려면 학습 기록 JSON 백업을 가져옵니다. HTTP와 HTTPS도 출처가 다르므로 위 HTTPS 주소를 사용하세요.

## 저장과 사용자 전환

IndexedDB `computer-security-cbt:v1`의 `users`와 `profiles` 저장소를 사용합니다. 탭 로그인은 sessionStorage `computer-security-cbt:tab-session:v1`, 기록 변경 알림은 BroadcastChannel `computer-security-cbt:changes`입니다. 빅데이터 사이트의 DB·키·계정은 열지 않습니다.

사용자별 진도·최근 강의·북마크·진행 중인 응시·이력·오답·테마·풀이 설정·교재 복습 체크를 분리합니다. 다른 탭에서 다른 계정으로 로그인할 수 있으며 알림을 받은 탭은 자기 사용자 변경에만 반응합니다. 같은 사용자를 여러 탭에서 편집하면 최신 IndexedDB 값을 읽는 트랜잭션으로 저장합니다. 동일 응시 제출은 응시 ID로 중복을 막습니다.

새로고침하면 탭의 세션과 기록을 복원합니다. 브라우저를 닫아도 IndexedDB 기록은 남습니다. 새 탭·브라우저 재시작 시 세션 복원 여부는 브라우저 정책에 따라 다르므로 계정으로 다시 로그인하면 저장된 기록을 불러옵니다. 로그아웃은 게스트로 전환하며 계정 기록을 삭제하지 않습니다. 게스트는 이 브라우저의 공통 프로필이며 여러 게스트 탭에서 공유합니다.

게스트 이전은 로그인/가입 화면의 **게스트 학습 기록을 이 계정에 합치기**를 직접 선택했을 때만 실행합니다. 이전해도 게스트 원본을 삭제하지 않습니다.

비밀번호는 원문을 저장하지 않습니다. Web Crypto의 PBKDF2-HMAC-SHA-256, 600,000회, 계정별 무작위 16바이트 salt로 검증값을 만듭니다. [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)을 참고했습니다. HTTPS/localhost에서 실행합니다. 이 기능은 로컬 학습 기록을 나누며 서버 인증·기록 암호화·기기 간 동기화·비밀번호 분실 복구를 제공하지 않습니다.

## 백업

1. 계정·백업 → 백업과 복원에서 현재 사용자 이름을 확인합니다.
2. 내 기록 내보내기를 누르면 JSON을 내려받습니다. 인증정보와 다른 프로필은 포함하지 않습니다.
3. 복원 정책을 선택하고 파일을 고릅니다. `합치기`는 ID가 같은 항목의 최신 값을 사용하고, `덮어쓰기`는 현재 사용자의 학습 기록을 교체합니다.
4. 검증한 기록 수와 초안 유무를 확인하고 적용 버튼을 누릅니다. 검증만으로 기록을 변경하지 않습니다.

형식 `app: computer-security-cbt`, `schemaVersion: 1`, UTF-8 10MB 제한을 검사합니다. 강의·문항·선지 ID, 순서·참조, 소유자 일관성, 시간·형식, 서술 자기 평가 조건을 검사하고 점수를 재계산합니다. 가져온 기록은 현재 사용자에게 다시 연결합니다. 다른 앱의 백업·미지원 버전·없는 콘텐츠·다른 소유자가 섞인 파일은 거부합니다. 실패하면 기존 기록을 유지합니다.

브라우저 데이터 삭제·다른 기기 사용 전에 JSON을 따로 보관하세요. 백업에는 답안과 학습 이력이 있으므로 본인이 관리하는 위치에 보관합니다.
